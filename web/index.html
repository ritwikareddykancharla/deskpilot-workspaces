DeskPilot — Governed Agentic Workspace Runtime, Automated POSIX Remediator & Bedrock Co-Pilot

A zero-dependency Python 3.12 control plane for shared human-AI cloud developer workspaces: runs policy-cleared POSIX inspection and test commands inside isolated /tmp sandboxes (subprocess.run(..., shell=False)), blocks secret, clipboard, and network exfiltration before execution, repairs local filesystem/PID/permission drift automatically, and records SHA-256 hash-chained SQLite WAL audit rows alongside Amazon Bedrock (us.amazon.nova-lite-v1:0).

§01 · Problem Statement

Why Shared Human + AI Cloud Workspaces Need OS-Level Confinement

When an engineer and an AI agent share the same cloud workspace side by side, relying on LLM system prompts alone leaves credentials, local files, and workspace stability exposed.

Agentic WorkSpaces Security & Continuity

💡 In Plain English (What DeskPilot Does in 3 Sentences)

1. The Core Problem: Modern cloud developer environments want an AI Co-Pilot working right next to a human developer in the same workspace—running unit tests, checking logs, and preparing config fixes—without risking the AI reading .env secrets, copying proprietary code to the host clipboard, uploading data externally, or accidentally deleting files.
2. How DeskPilot Enforces Safety: Before any command proposed by Amazon Bedrock Nova touches the OS, DeskPilot's deterministic Python policy gate inspects the parsed tokens in 0.18 ms (p50): read-only checks (like ls or python3 -m unittest) run automatically inside a confined /tmp directory with shell=False and scrubbed environment variables; file mutations pause until the human clicks Co-Sign; and secret/clipboard/network exfiltration commands are blocked outright.
3. Self-Healing & Tamper-Evident Audit: DeskPilot also watches the workspace filesystem for common developer-environment failures—compressing runaway debug logs with gzip, clearing dead worker PID lockfiles after checking os.kill(pid, 0), tightening world-readable signing keys back to 0600, and restoring broken JSON configs—while chaining every action into a tamper-evident SQLite WAL SHA-256 ledger.

GAP 01 · CREDENTIAL & EGRESS LEAKS

Unconfined Subprocesses Leak Secrets

A prompt-injected agent with raw shell access can run cat .env, dump printenv AWS credentials, copy proprietary files via pbcopy/xclip, or POST source code out via curl and nc.

GAP 02 · UNGATED FILE MUTATIONS

Silent Destructive Edits Mid-Session

Without a pre-execution co-sign gate, an autonomous debugging loop can overwrite active configuration files, run rm -rf, or alter permissions while the developer is actively editing code.

GAP 03 · LOCAL WORKSPACE DRIFT

Stale PID Locks & Log Exhaustion

Long-lived cloud workspaces degrade when runaway debug logs fill local volumes, crashed background processes leave stale .lock files, or session keys drift to insecure 0644 modes.

GAP 04 · MUTABLE AUDIT TRAILS

Plaintext Logs Lack Tamper Evidence

Ordinary text logs cannot prove post-incident integrity. Enterprise workspaces require an append-only SQLite WAL ledger linking every command, verdict, and exit code with SHA-256 hashes.

§03 · Implementation

Codebase Architecture (Paired Plain-English Intuition & Under-the-Hood Mechanics)

Every subsystem in deskpilot/ is written in zero-dependency Python 3.12 stdlib, pairing clear operational boundaries with concrete POSIX syscalls and SQLite WAL persistence.

10/10 Unit Tests Passing
MODULE 01 · POLICY GATE & /tmp SUBPROCESS SANDBOX deskpilot/workspace_sandbox.py
Plain-English Intuition Think of the sandbox as a locked room on disk for each workspace: the AI can look at source code and run unit tests inside that room, cannot open the .env safe, cannot pass notes out through the clipboard or internet, and must ask permission before copying or creating files.
Under the Hood evaluate_command_policy() parses commands with shlex.split() in 0.18 ms p50, blocks shell chaining (; && | $()), resolves every path argument via Path.resolve().is_relative_to(ws_root), strips host/AWS env vars, and spawns approved binaries via subprocess.run(argv, shell=False, timeout=4.0) (8.42 ms p50).
MODULE 02 · POSIX WORKSPACE HEALTH REMEDIATOR deskpilot/health_remediator.py
Plain-English Intuition Cloud developer workspaces often break from mundane local clutter—a runaway log filling up disk, a crashed process leaving a lockfile behind, an expired session config, or a typo in a tool JSON file. DeskPilot detects and repairs all four automatically before the developer's workflow stalls.
Under the Hood execute_real_remediation() compresses 524,288 B trace logs with gzip into archive/worker_debug.log.gz, probes lockfile PIDs via os.kill(pid, 0) (unlinking only on ProcessLookupError), rotates HMAC-SHA256 session tokens + os.chmod(0o600), atomically swaps broken JSON via os.replace(), and verifies recovery by running python3 app/healthcheck.py (39.77 ms p50).
MODULE 03 · SQLITE WAL HASH-CHAINED AUDIT LEDGER deskpilot/audit_ledger.py
Plain-English Intuition Every single command the AI attempts—whether allowed, paused for Co-Sign, or blocked as an attack—is written into a tamper-evident receipt book where editing any past line breaks the mathematical signature of every line after it.
Under the Hood SQLiteAuditLedger runs SQLite in PRAGMA journal_mode=WAL and computes sha256(canonical_json(event + prev_hash)) on every insert. verify_chain_integrity() recomputes and validates all 76 benchmark rows end-to-end in 1.427 ms, catching single-row tampering in unit test test_08.
MODULE 04 · BEDROCK NOVA CO-PILOT & LAMBDA API deskpilot/vdi_control_plane.py · server.py
Plain-English Intuition Instead of editing the developer's open files directly, Amazon Bedrock Nova acts as a polite pair-programmer: it runs read-only diagnostics, writes its proposed notes into a separate proposals/ folder, and writes clear post-fix incident summaries.
Under the Hood invoke_bedrock_nova() calls us.amazon.nova-lite-v1:0 via the AWS Bedrock Converse API (776.5 ms p50 across 26 measured calls, 387.5 mean tokens), extracts structured JSON command plans, merges any explicit prompt vectors so injections never bypass policy evaluation, and serves CloudFront /api/* via lambda_handler().
§04 · Design Tradeoffs

Engineering Tradeoffs & Operational Constraints

Deliberate architectural choices balancing security isolation, execution latency, and zero-idle serverless cost.

First-Principles Decisions
TRADEOFF 01 · SHELL=FALSE VS PIPELINES

Rejecting Shell Metacharacters Eliminates Chaining Attacks

Plain-English Intuition: Disallowing pipes (|) and semicolons (;) means the AI must run two separate simple commands instead of one clever shell one-liner—but it makes classic command-injection attacks structurally impossible.
Under the Hood: By rejecting SHELL_INJECTION_RE and invoking subprocess.run(argv, shell=False) directly via execve without /bin/sh, arguments like ; cat .env are never interpreted by a shell parser.

TRADEOFF 02 · ORTHOGONAL CO-SIGN & DLP TIERS

Human Approval Never Unlocks Secret or Network Egress

Plain-English Intuition: Clicking "Approve" when fatigued should allow the AI to copy a config file inside the project—never allow it to send secrets to an external URL.
Under the Hood: allow_elevated=True only transitions MUTATING_BINARIES (cp, mv, mkdir, touch) from COSIGN_REQUIRED to COSIGNED_EXECUTED. All 12/12 adversarial benchmark probes were run with allow_elevated=True and still blocked 100.0%.

TRADEOFF 03 · EPHEMERAL LAMBDA /tmp + SQLITE WAL

Zero Standing Cost vs Cross-Container Persistence

Plain-English Intuition: Hosting workspaces inside AWS Lambda /tmp gives instant, real Linux filesystem execution at near-zero idle cost, with the tradeoff that state resets when AWS recycles warm containers.
Under the Hood: In a multi-hour enterprise deployment, the same PosixWorkspaceSandbox and SQLiteAuditLedger mount onto Amazon EFS or EBS per-user volumes without changing a single line of policy code.

TRADEOFF 04 · DETERMINISTIC GATE + LLM PLANNER

Sub-Millisecond Enforcement, Asynchronous Reasoning

Plain-English Intuition: Never use a slow, probabilistic LLM to decide whether a shell command is safe when a deterministic parser can check it 4,000× faster.
Under the Hood: Policy evaluation runs in 0.18 ms p50 and OS remediation runs in 39.77 ms p50 in pure Python; us.amazon.nova-lite-v1:0 (776.5 ms p50) is reserved strictly for natural-language planning and post-fix SRE reporting.

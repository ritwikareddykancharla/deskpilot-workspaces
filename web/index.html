DeskPilot: A Safe Shared Workspace Where Engineers and AI Agents Code Together

When an AI assistant works directly inside your cloud dev environment, a bad command can expose your .env secrets or overwrite files without asking, and full disks or stuck background jobs can quietly break the workspace. DeskPilot sits between the AI and your workspace: it runs read-only checks automatically, pauses file changes for your 1-click approval, blocks secret leaks, and fixes common workspace hangs on its own.

01 · Problem

Problem

Sharing a cloud development workspace with an AI assistant exposes local credentials, active source files, workspace processes, and audit logs when commands run directly in an unrestricted shell.

Shared Cloud Workspaces

Overview

DeskPilot sits between Amazon Bedrock and the operating system inside a shared developer workspace. Every proposed command passes through a Python policy check in 0.18 ms (p50) before any process starts. Read-only checks such as ls and unit tests run automatically inside an isolated workspace directory (subprocess.run(..., shell=False) with scrubbed environment variables). File changes wait for 1-click approval, and commands that read .env secrets, copy to the clipboard, or open network connections are blocked. DeskPilot also repairs four common local workspace issues (bloated debug logs, stale process lockfiles, expired session tokens, and broken JSON configs) and appends every event to a hash-linked SQLite WAL log.

01 · CREDENTIAL LEAKS

Secrets and Source Code Can Leak Out

A prompt-injected assistant with raw shell access can read .env files, dump printenv cloud tokens, copy code to the host clipboard via pbcopy or xclip, or upload files with curl and nc.

02 · UNAPPROVED EDITS

Unchecked Commands Overwrite Active Work

Without an approval step before execution, an automated debugging loop can overwrite config files, alter key permissions, or run rm -rf while an engineer is editing code.

03 · WORKSPACE DRIFT

Long-Lived Cloud Desktops Stall Over Time

Over days of use, runaway debug logs fill local disks, crashed background workers leave orphaned .lock files behind, session tokens expire, and tool configs pick up syntax errors.

04 · EDITABLE LOGS

Ordinary Text Logs Can Be Rewritten

Standard log files cannot prove whether an incident trail was edited afterward. Security teams need an append-only history where altering any past line breaks a verifiable cryptographic hash chain.

03 · Implementation

Implementation

DeskPilot uses standard-library Python 3.12 with zero third-party runtime packages. Four modules handle command checking and process isolation, workspace repair, hash-chained SQLite logging, and Bedrock API integration.

10 / 10 Unit Tests Passing
01 · COMMAND SAFETY GATE & ISOLATED RUNNER deskpilot/workspace_sandbox.py
Each workspace is an isolated directory on disk. The AI assistant can inspect source code and run unit tests automatically, cannot open .env secrets or send data over the clipboard or network, and must pause for approval before copying, moving, or creating files.
evaluate_command_policy() splits commands with shlex.split() in 0.18 ms (p50), rejects shell chaining operators (;, &&, ||, |, $(), >), resolves every path via Path.resolve().is_relative_to(ws_root) to stop ../ escapes, strips host and AWS environment variables, and spawns approved binaries with subprocess.run(argv, shell=False, timeout=4.0) (8.418 ms p50).
02 · AUTOMATIC WORKSPACE SELF-REPAIR deskpilot/health_remediator.py
Cloud developer workspaces often stall on local file and process issues: debug logs filling the disk, crashed background jobs leaving lockfiles behind, expired session tokens, or broken JSON config files. DeskPilot detects and repairs all four automatically.
execute_real_remediation() compresses 524,288 B trace logs with gzip into var/log/archive/worker_debug.log.gz, checks lockfile PIDs with os.kill(pid, 0) (unlinking only when ProcessLookupError confirms the process is dead), rotates HMAC-SHA256 tokens and tightens key permissions via os.chmod(0o600), restores clean JSON configs atomically with os.replace(), and verifies recovery by running python3 app/healthcheck.py (39.772 ms p50).
03 · TAMPER-EVIDENT ACTION HISTORY deskpilot/audit_ledger.py
Every command proposed by an engineer or the AI is appended to an audit log. Editing any historical row changes its hash and invalidates every row recorded after it.
SQLiteAuditLedger runs SQLite with PRAGMA journal_mode=WAL and computes SHA-256(canonical_json(event + prev_hash)) chained from GENESIS_DESKPILOT_SQLITE_0000. Calling verify_chain_integrity() re-hashes and checks all 76 benchmark entries end-to-end in 1.427 ms, catching single-row database edits in unit test test_08.
04 · AI TASK PLANNER & SERVERLESS API deskpilot/vdi_control_plane.py · server.py
Instead of editing open source files in place, Amazon Bedrock runs read-only checks to inspect code and test output, writes proposed changes into a separate proposals/ folder, and summarizes workspace repairs.
invoke_bedrock_nova() calls Amazon Bedrock (us.amazon.nova-lite-v1:0) via the Converse API (776.5 ms p50 across 26 calls, 387.5 mean tokens), parses structured JSON command lists, passes every command and any injected prompt strings through evaluate_command_policy(), and serves CloudFront /api/* routes through lambda_handler().
04 · Trade-Offs

Trade-Offs

Each design decision in DeskPilot trades shell convenience or cross-container persistence for predictable command boundaries and near-zero idle cost.

Design Decisions
01 · SHELL OPERATORS DISABLED

Separate Commands Instead of Shell Pipelines

Banning pipes (|), redirects (>), and semicolons (;) means the AI assistant cannot run shell one-liners and must issue separate simple commands instead. In exchange, rejecting SHELL_INJECTION_RE and calling subprocess.run(argv, shell=False) directly via execve without /bin/sh prevents injected arguments like ; cat .env from running as sub-commands.

02 · SCOPED 1-CLICK APPROVAL

File Approval Never Unlocks Secrets or Network Access

Approving a file edit lets the AI copy or create files inside the workspace directory, but never unlocks credential files or outbound network tools. Setting allow_elevated=True only permits local file operations (cp, mv, mkdir, touch, chmod). All 12 / 12 red-team secret and privilege attacks were benchmarked with approval enabled and still blocked 100%.

03 · LAMBDA /tmp VS PERSISTENT VOLUMES

Zero Idle Server Cost vs. Container Recycling

Running workspaces inside AWS Lambda /tmp gives this live demo real Linux processes, file permissions, and SQLite WAL storage at near-zero idle cost, with the trade-off that disk state resets when AWS recycles warm containers. In a persistent Amazon WorkSpaces deployment, PosixWorkspaceSandbox and SQLiteAuditLedger mount onto per-user EBS or EFS volumes without changing policy code.

04 · PYTHON RULES VS MODEL FILTERING

Sub-Millisecond Python Checks Before Execution

Asking an LLM whether a shell command is safe adds hundreds of milliseconds of latency and remains vulnerable to prompt injection. DeskPilot checks commands in deterministic Python in 0.18 ms (p50) and uses Amazon Bedrock (776.5 ms p50) only for task planning and post-repair incident summaries.
